## 2025-02-23 - [Optimize NumPy Top-K Selection with argpartition]
**Learning:** `np.argsort` has O(N log N) complexity, causing performance bottlenecks during top-K candidate selection in large vector search indices (e.g., K3 MRL Indexer). For top-K selection without a full sort, `np.argpartition` provides O(N) complexity. In benchmarks, switching from `argsort` to `argpartition` for K=75 out of 100,000 vectors reduced the execution time from ~4.0ms down to ~0.36ms (a 10x+ improvement).
**Action:** When extracting top-K candidates from large NumPy arrays (e.g., scoring matrices, similarity calculations), always prioritize `np.argpartition` followed by sorting just the selected partition, rather than using `np.argsort` on the entire array.
## 2025-10-24 - Einsum Memory Optimization for MRL Indexer
**Learning:** During benchmarking, using `np.linalg.norm(..., axis=1, keepdims=True)` on a matrix to compute cosine similarity creates a full NxD intermediate normalized matrix in memory. In an MRL indexer processing many vectors, this leads to significant cache-misses and memory allocations.
**Action:** Replace `m / np.linalg.norm(m)` with computing 1D squared norms via `np.einsum('ij,ij->i', m, m)`. Compute raw dot products `np.dot(m, q)` and scale the results by `((np.sqrt(m_sq_norms) + 1e-9) * (np.sqrt(q_sq_norm) + 1e-9))`. This prevents the large intermediate matrix allocation, yielding an observed ~8-10x speedup in normalization cache setup (e.g. 28.9ms to 3.5ms for N=100k) and eliminates O(NxD) transient memory overhead in hot paths without changing math output.
