## 2025-02-23 - [Optimize NumPy Top-K Selection with argpartition]
**Learning:** `np.argsort` has O(N log N) complexity, causing performance bottlenecks during top-K candidate selection in large vector search indices (e.g., K3 MRL Indexer). For top-K selection without a full sort, `np.argpartition` provides O(N) complexity. In benchmarks, switching from `argsort` to `argpartition` for K=75 out of 100,000 vectors reduced the execution time from ~4.0ms down to ~0.36ms (a 10x+ improvement).
**Action:** When extracting top-K candidates from large NumPy arrays (e.g., scoring matrices, similarity calculations), always prioritize `np.argpartition` followed by sorting just the selected partition, rather than using `np.argsort` on the entire array.
## 2025-02-23 - [Optimize String Splitting with Native str.rfind]
**Learning:** In Python, breaking a large string into small chunks by splitting the entire string on newlines (`text.split("\n")`) creates a large number of intermediate string objects in memory and requires a slow Python-level loop to reconstruct chunks. Using native `str.rfind('\n', start, end)` to scan for segment boundaries within the raw string and slicing it (`text[start:last_newline]`) avoids creating an intermediate list of all lines, performing the heavy lifting in C. In benchmarks, this optimized approach yielded an ~4x speedup for chunking long texts.
**Action:** When partitioning large strings based on a delimiter into fixed-size chunks, prioritize searching for boundaries via native `rfind()` or `find()` and slicing directly over splitting the entire string upfront.
