## 2025-02-23 - [Optimize NumPy Top-K Selection with argpartition]
**Learning:** `np.argsort` has O(N log N) complexity, causing performance bottlenecks during top-K candidate selection in large vector search indices (e.g., K3 MRL Indexer). For top-K selection without a full sort, `np.argpartition` provides O(N) complexity. In benchmarks, switching from `argsort` to `argpartition` for K=75 out of 100,000 vectors reduced the execution time from ~4.0ms down to ~0.36ms (a 10x+ improvement).
**Action:** When extracting top-K candidates from large NumPy arrays (e.g., scoring matrices, similarity calculations), always prioritize `np.argpartition` followed by sorting just the selected partition, rather than using `np.argsort` on the entire array.

## 2025-02-23 - [Optimize Hot Loop Object Instantiation and Matrix Norms]
**Learning:** Using `Path(file).suffix in extensions` inside an `os.walk` hot loop creates extreme overhead by instantiating `Path` objects repeatedly. Converting it to `file.endswith(ext_tuple)` avoids object instantiation entirely, providing a ~36x speedup. Furthermore, when normalizing large vector matrices or queries, replacing `np.linalg.norm(A, axis=1)` with `np.sqrt(np.einsum('ij,ij->i', A, A))` yields a ~4x speedup, and replacing `np.linalg.norm(v)` with `np.sqrt(np.dot(v, v))` yields a ~1.6x speedup by avoiding intermediate array allocations and generalization overheads in NumPy.
**Action:** Always prefer native string methods (like `endswith()`) over class instantiations (like `Path()`) within large iterative loops to avoid heavy overhead. For fast L2 normalization on NumPy matrices, heavily prefer `einsum` or squared operations `dot` instead of `np.linalg.norm`.
